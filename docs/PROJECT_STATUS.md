# びくたん Desktop 現状メモ

最終更新: 2026-07-27

## 何のアプリか

Live2Dキャラクター「びくたん」をデスクトップに常駐させる、Electron製のAIコンシェルジュアプリ。

サイト `bikunitan.online` で動いていた Live2D モデルの挙動をベースに、デスクトップ常駐、会話、読み上げ、自動セリフ、音声入力、ポモドーロ、音楽反応を追加している。

## 現在の大きな機能

- Live2D常駐
  - 透明・枠なし・最前面ウィンドウ
  - メニューバー常駐

  - セリフ履歴表示

  - びくたん自身の成長問答

## 音声認識の現状

音声入力は、ブラウザ側で録音した音声をWAV化し、main process から音声認識へ渡す構成。macOSではApple Speech frameworkを使う `native/speech-recognizer.app` を優先し、起動できない・権限がない場合はWhisperへ戻る。Apple Speechは対応端末では端末内認識を必須にし、非対応時はmacOS側のネットワーク認識を使う。

Whisperを明示する場合:

```text
BIKUNAVI_STT_ENGINE=whisper
```

Whisperの既定探索先:

既定の探索先:

- `BIKUNAVI_WHISPER_BIN`
- `/opt/homebrew/bin/whisper-cli`
- `/usr/local/bin/whisper-cli`
- `native/stt/<platform>-<arch>/whisper-cli`
- 旧名 `main` / `main.exe`

既定モデル:

```text
models/ggml-base.bin
```

メモ:

- `ggml-base.bin` は軽いが、書き起こし精度はまだ粗い。
- macOSではApple Speechが本命になったため、Whisperは非対応環境とフォールバック用。
- 別のモデルを試す時は `BIKUNAVI_WHISPER_MODEL` で指定する（`small-q5_1` は実機で5〜11秒かかり、2026-07-23に削除した）。
- 配布版では Homebrew 依存にできないため、OS/CPU別の同梱バイナリ方針を決める必要がある。

## 既知の注意点

- UI部品が小さい吹き出し内に密集しやすい。
- コピーはアイコン化済み、マイクは拡大済み。ただし履歴、ソースURL、入力欄、送信ボタンを含む全体の整理はまだ必要。
- 音声入力の録音には `ScriptProcessorNode` を使っている。コールバックがLive2D描画と同じスレッドで走るため取りこぼしを疑ったが、2026-07-22の常用計測では15,604コールバック中0件だった（`audio-meter-utils.js`）。`AudioWorkletNode` への移行は当面見送り、計測だけ続ける。
- 配布前に Electron のセキュリティ設定、署名、公証、STTバイナリ同梱を整理する。
- Windows対応は設計方針のみ。STT、読み上げ、音楽検出、常駐UIの代替実装が必要。

## v0.3.0 での主な変更（2026-07-27）

- 初期値OFFの「ハンズフリー会話（試験中）」を追加。ON時だけマイクを継続待機し、使用中は画面下部と会話欄のマイク表示で明示する
- Web AudioのRMSと環境ノイズ追従を使うローカルVADを追加。発話開始前の短い音も取りこぼさないようプリロールを保持し、無音が続いた時点で発話を確定する
- 確定した音声だけを同梱WhisperでMac内文字起こしし、そのまま会話へ送信する。音声ファイルは成否にかかわらず処理後に削除する
- 読み上げ中に加えて、回答の生成中も割り込めるようにした。高い閾値で発話を検知したら、生成中の会話を畳んでから聞き取りへ移る。中断した回答はエラー表示も履歴も残さない
- 実機調整: 発話終了の無音待ちを850msから700msへ短縮。`small-q5_1`は認識に約5〜11秒かかったため、通常は速度優先の `base`を使う。認識時間は継続してログに残す
- 実環境の短い音を発話として拾うため、VADの開始閾値を0.035から0.045、継続時間を300msから360msへ調整。常時待機中に発生した「バイバーイ」だけの典型的な無音誤認識も会話へ送らない
- 雑音の中で声を拾えない問題を修正。開始しきい値は環境ノイズ×4で青天井に上がり、実測で0.106（発話RMSの中央値0.107とほぼ同じ＝声が埋もれる高さ）まで到達していた。倍率を3へ下げ、上限0.075で頭打ちにする。読み上げ中の自己音声よけ（0.09）はこの上限より優先される
- 拾えなかった音は今までログに残らず調整が勘になっていたため、「下限は超えたがしきい値に届かなかった」音を near miss として記録する（out.logの「Hands-free near miss」）
- macOSの文字起こし比較用にApple Speech framework経路を追加。初回の音声入力時に権限を許可し、認識結果・処理時間・信頼度・端末内処理かどうかをログで比較する
- Apple Speechが「発話なし」と判定した音はWhisperへ渡さず、空結果のまま終了する。環境音を別の言葉に補うフォールバックを防ぐ
- 2026-07-22に実機で試用。184発話でWhisperへのフォールバックは0件、認識は350〜860ms・すべて端末内で完了した。`small-q5_1` の5〜11秒と比べて桁違いに速く、これを受けてWhisperの `small-q5_1` は配布へ同梱しない方針にした
- `SFTranscriptionSegment.confidence` は値が返る（0.19〜0.98を確認）。0.000が並んでいたのは無音判定の空結果だった。ログは値がある時だけ出す
- 独り言に「続きもの」を追加。まとめ生成の中で2〜4行ひとつながりの話題を作り、`cont||セリフ` で印を付ける。話している間は日記の振り返り・質問・占いを挟まず、いつもの30秒〜2分ではなく約7秒で次の行へ進む。話しかけられた時点で続きは捨てる（会話のあとに蒸し返さない）
- 続きものの間は吹き出しを消さず、本文だけ差し替える。消して出し直すと同じ話題でも別々の発言に見えるため。次の行までは約3.5秒
- 会話欄のマイクを長押し（600ms）でハンズフリー会話をON/OFFできる。トレイメニューまで行かずに切り替えるための入口。短いクリックは今までどおり単発録音
- 作り置きの独り言に生成時の時間帯を刻み、時間帯をまたいだ「深夜0時を過ぎましたね」のような行は話す前に捨てる（`idle-freshness-utils.js`）。6時間以上前の行は時間に触れていなくても捨てる
- 触られない時間が続くとだんだんうとうとする。まぶたが下り、まばたきの間隔が詰まり、そのまま薄くなっていく。**「待機だから薄い」ではなく「眠ってしまったから薄い」に見えるようにするため**、薄さは眠さへ連動させている（昼は約150秒、夜20時〜翌5時は2.4倍の速さで眠りきる）。ホバー・会話・読み上げ・ドラッグ・ポモドーロ中は即座に起きて元に戻る
- ミュートボタンをびくたんアイコンから音量マーク（🔊/🔇）へ戻した。ミュート状態はびくたん本人が×マスクを着けて見せるので、ボタンと二重になっていた
- ホバー中の口パクを息づかい程度へ弱めた。読み上げ中と同じ振幅で動いており、喋っているように見えていた
- びくたんの「いま何をしているか」を、実際に持っているデータに根ざしたものだけにした。「今日の予定を少し整えています」「Live2Dまわりの用語をノートにしています」「次のポモドーロの計画を立てる」など、**予定管理もノートも計画機能も無いのに実体のある作業のように語る固定文**が独り言と会話の両方に入っていた。ことば帳・思い出帳・日記・記事の評価・集めた見出しの件数か、体の動き（フードの向き、深呼吸）に限定する
- 待機中だけキャラクターを薄くできるようにした（🖥 表示・サイズ →「待機中はうすく表示」、初期値OFF）。ホバー・ドラッグ・会話・読み上げ・履歴表示・ポモドーロ中は元の濃さへ戻る。`BrowserWindow.setOpacity()` ではなく canvas へCSSで掛ける（ウィンドウ全体だと吹き出しまで読めなくなるため）。切り替えは520msでなじませる
- クリック透過の当たり判定は、ホバー検知とは別に持つ。ホバー用の判定はキャラと吹き出しの間の余白（左右28px）まで含むため、そのまま使うと**吹き出しが出ている間だけ後ろを触れなくなる**（「触れる時と触れない時がある」の原因）。クリックを受け取るのは、キャラ本体・吹き出しの実矩形・ポモドーロ・音量コントロールの上だけにする
- びくたん本体・吹き出し以外の透明な部分で、クリックを後ろのウィンドウへ通せるようにした（🖥 表示・サイズ →「びくたん以外へクリックを通す」、初期値OFF・state.jsonへ保存）。mainが常時カーソルをポーリングして本体／吹き出し／操作UIの上かを判定し、その上だけウィンドウがクリックを受け取る。ドラッグ移動と会話はそのまま使える
- 修正: 非表示にしても一定時間で勝手に再表示される問題。自動セリフ・スリープ復帰の挨拶・初回案内が、表示状態を見ずにウィンドウを出し直していた。非表示の意思を覚えて、自動の経路では出し直さない（トレイから明示的に開いた時は解除される）
- 表示中のセリフに表示時刻を持たせ、10分以上前のものは「いま返信された先」として会話AIへ渡さない。古い独り言へ話が寄って、目の前の発言が無視されるのを防ぐ
- ハンズフリーの聞き取りは確信度で3段階に分ける（`classifyTranscriptConfidence`）。**0.15未満は環境音の誤認識とみなして会話へ送らず黙って捨てる**、0.15〜0.45は「〜で合ってますか？」と一度だけ聞き返す、0.45以上はそのまま答える。手入力と単発録音は本人が目で確かめてから送るため対象外。確信度を返さない経路（Whisper）は0が返るので判定せず素通しする
- ニュース・情報の出典に「👍 / 👎」を付けられるようにした（`source-rating-utils.js`）。旧「☆保存」の置き換えで、保存済みの記事はグッドとして引き継ぐ。同じボタンをもう一度押すと取り消し、反対側を押すと付け替わる（両方は立たない）。グッドはトレイの「気になる記事」から見返せる。評価は `state.json` の `sourceRatings` にだけ置き、データ管理の「気になる記事を消す」で評価ごと消える。話題選びへの反映は未実装
- デザイン系ニュースの検索クエリを見直した。「フォント」「配色」は日常語で、サッカーの加入ムービーやファッション記事が大量に混ざっていた（2026-07-26の実測で12件中4件がデザイン記事ではなかった）。フレーズ検索へ変え、「フォント」→「フリーフォント」、「配色」を外し、「ロゴデザイン」「デザインシステム」を追加。**「Figma」は日本語圏でフィギュアの「figma」と衝突するため入れない**
- 同じ記事がYahoo!ニュース経由などで二重に流れてくるので、見出しを正規化して重複を弾く（括弧の全半角と配信元の違いを均す）
- 評価を話題選びへ反映する（`topic-preference-utils.js`）。見出しからカタカナ語・英数字語・漢字熟語を抜いて集計し、👎が優勢な語・媒体を含む見出しは収集段階で落とす（ただし25%は通して偏りを防ぐ）。👍が優勢な傾向は独り言の生成プロンプトへ渡す。同じ語が2回以上評価されるまでは判断材料にしない。実データでは同じHacker Newsに👍と👎が混ざっており、媒体だけでは判定できなかった
- 教わった言葉を2つ組み合わせて話す回を入れた（45%の確率、語が2つ以上ある時だけ）。「カフェラテ」と「お昼寝」のように、意味を説明せず二つが自然につながる場面として話させる。成立したかは out.log の「Idle vocabulary pair」で分かる
- ことば帳で教わった語が独り言に出すぎないようにした（`idle-vocabulary-utils.js`）。1バッチ内で同じ語を使う話題は2つまで。既存の重複排除は文の類似度なので「お昼寝したい」「お昼寝の時間」のように文が違うと素通りしていた。ことば帳のプロンプトにも、音楽の好みと同じ強さの抑制（使うこと自体を目的にしない・同じ語を繰り返さない）を追加。使われ方は out.log の「Idle vocabulary」で数として見える
- 選択肢ボタンを押した時は、そのボタンが付いていたセリフをそのまま返信先として渡す。以前は `runChat` が改めて「表示中のセリフ」から推測し直しており、直前の会話が履歴に残っているとそちらへ引っ張られて話がズレた（実例: 「高いところ…ませんか？」に「わかる」と答えたら、2つ前の文具の話が返ってきた）
- 返信先の判定は out.log の「Chat context」で追える
- 「？」で終わる独り言に選択肢ボタンを出す（`idle-choice-utils.js`）。語尾から共感／許可・提案／Yes-Noを見分け、疑問詞のある質問（「何を〜？」）には出さない。選択肢はAIに作らせずローカルで用意する。独り言の出力形式へ列を足すと `source-utils.js` の列順回収パスと衝突するため
- 2026-07-25の実測で、受理した75件のうち33件が3文字以下、確信度0.45未満が24件あった。うち `11文字/0.005`・`7文字/0.005`・`5文字/0.003` のように文字数と確信度が釣り合わないものが多く、環境音がそのまま会話AIへ届いていた。しきい値は暫定で、out.logの「Hands-free transcript ignore / confirm / trusted」で較正する
- 雑談用のGeminiを `3.1 Flash-Lite` から `3.5 Flash-Lite` へ更新。短い報告に過剰な称賛・助言・質問を足さない、謎の固有名詞を創作しない、挨拶で過去話を急に持ち出さない、呼び名を連呼しないルールを追加
- Geminiが混雑した時は `3.5 Flash-Lite` から `3.1 Flash-Lite` へ自動退避。両方使えない時もAPIキー設定エラーと混同せず、一時的な混雑と表示する
